# The Market Reading

Version: 4.0
Goal: Read a market at Time0, before any deal, and decide what the seller has to be built to do. The reading says whether buyers pay for the problem today, which cost stands in their way, whether a floor or a belief holds them out, whether the seller is built and paid for that cost, and one of pursue, restructure or decline. The motion an organization builds follows from this reading. It does not follow from the motion that worked for a seller in another market.

**Canonical reference:** [Constitution 7.0](../theory/01-foundation/00-tcg-constitution.md), claims 1 to 5. [01-motions.md](../theory/01-foundation/01-motions.md) carries the argument behind each step.

| | |
|---|---|
| **Inputs** | The workflow the product changes, with each touchpoint typed. Whatever the seller can source about the buyers in the market. |
| **Outputs** | An eleven-row ledger with a source and a fill status on every row. The cost in the way and the motion it names. Whether the purchase is plug-in or built-in for a typical buyer. A floor-or-belief reading. The work the seller lacks. Pursue, restructure or decline. The search ledger. |
| **Next step** | Pursue: publish the search ledger, run the [Deal Triage Calculator](./deal-triage-calculator.md) on the first buyer, and feed its counts back here. Restructure: build or partner for what is missing, then re-read. Decline: record why, and re-read when an adjacent market fills the ledger. |
| **Owner** | Whoever chooses the motion. A founder, a chief revenue officer, or the person about to hire for one. |

> [!IMPORTANT]
> **This instrument counts and it cites.** Every row is a number of named things or a yes or no. Every row carries the source that supplied it and one of three fill statuses. **Known** means a named source supplied it, including the seller's own deal readings in this market. **Inferred** means it was reasoned from the workflow, the touchpoint types or an adjacent market, and is unconfirmed here. **Unknown** means neither. A row without a source is not filled. The counts compare one market with another, and one market with itself over time. No count is scored and no line is drawn on one.

---

## Step 1: Name the workflow and the market

Write the workflow the product changes, one row per step. Mark each step as internal, performed by the product alone, or as a touchpoint where the product meets the buyer's system of record. Type every touchpoint.

| Step | Internal or touchpoint | Touchpoint type | Role that performs it at the buyer | System touched |
|---|---|---|---|---|
| | | Enrollment, supplementation, writeback, foundational sync, or shared context | | |

The five types hold in any vertical, and [integration-touchpoints.md](../theory/02-research/integration-touchpoints.md) carries them. A seller who cannot fill this table stops here. A product that cannot name its workflow has nothing to read a buyer against.

The market is the buyers who call the problem by one name and run a recognizable variant of this workflow. Name them. Count the buyers and a typical contract value, each with a source and a fill status, because Step 6 asks whether the deals this market can produce repay what the seller must build.

---

## Step 2: Do buyers pay for the problem today?

Read this before any cost. A buyer that does not want the change shows up as a cost, usually search, and no work on a cost moves it.

| Row | What to count | Count | Source | Fill |
|---|---|---|---|---|
| V1 | Buyers that pay for the problem today: staff hours on a workaround, an incumbent tool, a consultant or an internal build | | | |
| V2 | Buyers with a dated reason to act and a budget owner this year | | | |

**Where V1 is zero.** In a category buyers already name, zero means decline. In a category nobody has named, no buyer pays for the problem yet, and that looks the same as no value. The proposed sign there is whether buyers begin paying anyone for the problem, rivals and internal builds included, once the category has been taught. [Open question 66](../theory/01-foundation/07-open-questions.md) records that this reading is untested.

---

## Step 3: Read the workflow and the organization

Claim 2 says two things a leader can see predict the cost in the way: the workflow and the buyer's organization. The workflow has two readings, how *settled* it is and how *entangled* it is. Fill each row for a typical buyer.

| Row | Reads | What to count | Count | Source | Fill |
|---|---|---|---|---|---|
| W1 | Settled | Ask three people at a buyer how the work is done. Count the buyers where the procedure is written, followed and carries volumes for its exceptions, those where people call it out of date, and those where the three answers differ | | | |
| W2 | Settled | Who wrote the workflow down: a regulator, an industry standard, or each buyer for itself. A regulator's version makes buyers alike, and each buyer's own makes them differ | | | |
| W3 | Entangled | Touchpoints, counted by type, from Step 1 | | | |
| W4 | Entangled | Procedures a named group performs differently after go-live | | | |
| O1 | Organization | Decision roles that can say no at a typical buyer | | | |
| O2 | Organization | Formal bodies the buyer's rules require at a typical contract value, such as procurement, a security review or a committee, and the spend threshold that brings each in | | | |
| S1 | Search | Whether buyers use a name for the problem, and which | | | |
| S2 | Search | Whether this seller holds a path to these buyers today: a vendor program, a marketplace, a purchasing consortium, a channel | | | |
| S3 | Search | Alternatives a typical buyer names: vendors, plus building it, plus doing nothing. Whether published material lets a buyer compare them | | | |

**Deriving O1 before any buyer is met.** The roles follow the touchpoint types. Writeback brings whoever owns the record and whoever polices it, enrollment whoever owns the operation the trigger sits in, foundational sync whoever owns master data, and shared context security. Add whoever pays. The list is Inferred until deal readings confirm it.

**Plug-in or built-in.** A *plug-in* purchase works on arrival: the buyer can try it on its own work and walk away having stranded nothing. A *built-in* purchase has either side build something that is worth less anywhere else, and W3 and W4 list what. Read which it is for a typical buyer. The Deal Triage Calculator asks claim 6's three tests of one buyer.

**The reading.**

| What the rows show | The cost in the way | The motion |
|---|---|---|
| Most buyers have no settled procedure (W1), or cannot name the problem (S1) | Search | Search-led, by teaching. Give the buyer a hypothesis about its own workflow |
| Buyers name the problem, and this seller holds no path to them (S2) | Search | Search-led, by a channel |
| The workflow is settled, and the purchase is built-in for a typical buyer (W3, W4) | Implementation | Implementation-led |
| More than one role can say no, or the buyer's rules bring in a formal body at this price (O1, O2) | Consensus, and often implementation with it | Consensus-led, or both run together |
| None of these | None | Turnkey |

Two costs in the way means both motions run. Nothing here ranks them, and [open question 67](../theory/01-foundation/07-open-questions.md) says why.

**Turnkey does not hold on its own.** A market that is cheap to enter fills with sellers whose claims sound alike (claim 3). Re-read S3 whenever the number of vendors moves.

**Cross-check against where buyers stop.** Buyers stop in three places. They never look. They look and decide nothing. They sign and fail to adopt. Read which from the seller's own records. Before any deals, read it from public requests for proposal that never became a purchase and from interviews with buyers who chose no one. Where the rows and the stopping point disagree, the rows name the cause. A buyer that expects its organization to fight the change may never look, and the seller records a search problem.

## Step 4: A floor, or a belief?

One sign has two causes. Buyers name the problem and buy from no one, whichever seller they meet. The remedies differ, so read which cause it is.

| Reading | How to tell | Remedy |
|---|---|---|
| **A floor.** Part of the cost is set outside any deal (claim 4) | Ask whether a seller that lowered the cost would keep the return. If every seller in the category would share it, a floor holds the cost: message volume against the buyers' attention, their procurement and compliance rules, or whether anyone can attribute an outcome | Something shared across deals: a standard, a certification, a marketplace, a pre-approved contract. Fund it, wait for whoever will, or choose another market |
| **A belief.** The cost is within reach and buyers believe otherwise | Ask buyers who named the problem and bought from no one what they think the purchase takes, and compare the answers with rows W3 to S3. Buyers already in discovery cannot answer, because their beliefs did not keep them out | Show this seller's own cost with evidence buyers can check before they meet anyone. It goes in the search ledger in Step 7 |

Where this seller's own product sets the cost, lowering it is a product decision. No test yet tells a floor from a belief ([open question 34](../theory/01-foundation/07-open-questions.md)).

---

## Step 5: Is the seller built for this cost, and does it pay for it?

Claim 5 says a seller reaches only the buyers whose cost it is built to carry. For the cost in the way, both where two tie, name who does each piece of work today. Work counts as present when a named person or team does it now. Someone who could do it does not count.

| Cost in the way | The work the motion needs | Who does it today |
|---|---|---|
| Search | Define what the buyer chooses between. Hold a path to the buyer. Make a commitment that costs the seller something | |
| Consensus | Collect each decision role's concern one to one. Write an arrangement each role can accept. Keep a sponsor holding the decision together | |
| Implementation | Run discovery in the buyer's environment. Walk the buyer through how the project would fail. Agree a staged plan before signature. Hold a review after it | |

**Pay.** Write down what the seller's people are paid for today, and compare it with the cost in the way. Where little is in the way, pay on bookings and on speed from search to contract fits. Where implementation is in the way, part of the pay waits until the implementation confirms the scope. That works only if the seller has written down what a complete discovery is, so record yes or no on that definition. Without it, the definition comes first, and no representative is paid on an outcome they cannot affect.

The count of missing work says which cost the organization is built to carry. It is not a sum of money.

---

## Step 6: Pursue, restructure or decline

**Two overrides first.** Where V1 is zero in a named category, decline. Where Step 4 reads a floor, decline, unless this seller will fund the shared investment that lowers it.

| Step 5 reads | Reading |
|---|---|
| No work missing | **Pursue.** The organization is built to carry the cost these buyers have. |
| Work missing, and the market's buyers at the typical contract value can repay building it | **Restructure.** Build it or partner for it, then re-read. |
| Work missing, and too few buyers to repay it | **Decline.** |

The build is repaid across the market's deals, won and lost, so a thousand buyers who each buy once can carry it.

**The imitation check.** If the organization has already built a motion and this reading names a different cost, doubt the motion before the reading. The heavy version of the mistake has its own price. A seller that puts engineers into every deal charges all its buyers for them, and a lighter rival wins the buyers who never needed the help (claim 9).

**A thin ledger.** Report how many rows are Inferred or Unknown beside the reading. Many of them is a reason to treat the first deals as research and to say so. It is not a reason to decline.

---

## Step 7: The search ledger

On pursue, write the search ledger. It lives at the market and every deal in it reuses it. It lowers a buyer's search cost only if the buyer can complete it without the seller, so its evidence comes from parties other than this seller: analysts, review sites, marketplaces, certifications and peer references (claim 3).

| Alternative | Steps of the workflow it covers | Evidence that compares it, which the buyer can check | How a buyer reaches it | Added |
|---|---|---|---|---|
| Each named vendor S3 counts | | | | |
| Building it internally | | | | |
| Doing nothing | | | | |

**Done when** three buyers from the market who have not met the seller can say, from the ledger alone, which alternatives cover which steps and how to reach the seller. Each evidence cell has to pass the [Friction Allocation Diagnostic](./friction-allocation-diagnostic.md), or it is marked as a claim.

**Where Step 4 read a belief,** evidence of this seller's own consensus or implementation cost goes here too: published terms, an audited security report, implementation timelines with named references. It is the one kind of cell this seller may fill, and only with evidence a third party produced or a buyer can check.

**Maintain it.** Append entrants as they arrive, and re-test the evidence when cheap claims start to crowd out costly ones.

---

## Re-reading

Every deal reading in the market turns rows from Inferred or Unknown into Known. Deal readings come only from buyers who entered, so keep counts from buyers who declined or never answered apart. Otherwise each re-read drifts toward pursue.

Re-run this reading when the book of deal readings disagrees with it, when the category moves ([01-motions.md](../theory/01-foundation/01-motions.md) section 4), and once a year regardless. If the deal readings disagree with each other more than with this reading, the market is two markets, and the seller splits it.

An adjacent market starts partly filled. A workflow that shares typed touchpoints with one the seller already serves starts with rows W3 and W4 Known. Rows O1 and O2 transfer less reliably, because decision roles are local to a market.

---

## What this does not settle

All four are recorded in [07-open-questions.md](../theory/01-foundation/07-open-questions.md).

- **No worked case yet.** Item 6 records the two-market test this reading has to pass.
- **The value reading in Step 2 is untested,** and so is its sign for an unnamed category. Item 66.
- **Two costs in the way are not ranked.** Item 67 proposes time against the buyer's window as the shared scale.
- **Step 5 counts work and not money.** It cannot tell work built once from work repeated in every deal. Item 56.
